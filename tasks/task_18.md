На основе анализа репозитория `https://github.com/ret80/VARDLOKKUR.git` я выявил точные причины обеих проблем. Ниже представлен подробный анализ, пошаговый план для ИИ-агентов, критерии успеха и протокол отчетности.

### 🔍 Корень проблемы

#### Проблема 1: Смещение безопасной зоны (дыры в тумане) относительно святилища
**Файл:** `src/game/renderers/fog/FogRenderer.ts` (метод `update`)
**Причина:** В методе `update()` координаты игрока и святилищ конвертируются из мировых единиц в UV-координаты шейдера (0..1) через деление на `screenW`/`screenH`, полученных из `r.getScreenSize()` (возвращает `app.screen.width/height`).

Однако `app.screen.width/height` — это **логические пиксели PixiJS**, которые после `renderer.resize(viewW, viewH)` при `resolution: 1` должны быть равны `viewW`/`viewH`. На практике может возникать рассинхронизация:
- При ресайзе окна `ViewportController.apply()` вызывает `renderer.resize(viewW, viewH)`, что обновляет `app.screen`.
- Но `getScreenSize()` может вернуть устаревшие значения, если вызван до завершения `resize()`.
- CSS-масштабирование canvas (`cv.style.width = "100%"`) означает, что визуальный размер экрана не обязательно совпадает с `app.screen`.

**Текущий код (FogRenderer.ts, строки 274-297):**
```typescript
const screenSize = r.getScreenSize();
const screenW = screenSize.w;
const screenH = screenSize.h;

const uvX = 0.5 + (playerPos.x - camPos.x) / screenW;
const uvY = 0.5 + (playerPos.y - camPos.y) / screenH;
// ...
const sx = 0.5 + (this._shrines[i].x - camPos.x) / screenW;
const sy = 0.5 + (this._shrines[i].y - camPos.y) / screenH;
```

**Математика проблемы:**
- Формула `0.5 + offset / divisor` предполагает, что `divisor` = ширина видимой области в тех же единицах, что и `offset`.
- `offset = playerPos - camPos` — в мировых единицах.
- `viewW/viewH` — ширина/высота видимой области мира в мировых единицах. **Это правильный делитель.**
- `screenW/screenH` — логические пиксели. При рассинхронизации с `viewW/viewH` дают неверный масштаб.

**Исправление:** Заменить `screenW`/`screenH` на `viewW`/`viewH` — они уже переданы в `update()` и находятся в тех же единицах, что и мировые координаты.

#### Проблема 2: Туман состоит из квадратов (пикселизация/растяжение)
**Файл:** `src/game/renderer/PixiJSRenderer.ts` (метод `createFullscreenQuad`)
**Причина:** Fullscreen-квадрат для применения шейдерного фильтра создается с размерами `this.app.screen.width` и `this.app.screen.height` (логические размеры, например 640×480). Когда к этому спрайту применяется фильтр, PixiJS рендерит его в текстуру размером с логический спрайт, а затем эта маленькая текстура растягивается на весь физический canvas (например, 1920×1080) через CSS или `resolution`. Это вызывает эффект "квадратов" (сильную пикселизацию).

#### Шаг 1: Исправление расчета UV-координат для святилищ и игрока
1. Открой файл `src/game/renderers/fog/FogRenderer.ts`.
2. В методе `update` найди блок расчета `uvX`, `uvY` и координат святилищ (`sx`, `sy`).
3. Замени деление на `screenW` / `screenH` на деление на `viewW` / `viewH`.
   **Было:**
   ```typescript
   const uvX = 0.5 + (playerPos.x - camPos.x) / screenW;
   const uvY = 0.5 + (playerPos.y - camPos.y) / screenH;
   // ...
   const sx = 0.5 + (this._shrines[i].x - camPos.x) / screenW;
   const sy = 0.5 + (this._shrines[i].y - camPos.y) / screenH;
   ```
   **Стало:**
   ```typescript
   const uvX = 0.5 + (playerPos.x - camPos.x) / viewW;
   const uvY = 0.5 + (playerPos.y - camPos.y) / viewH;
   // ...
   const sx = 0.5 + (this._shrines[i].x - camPos.x) / viewW;
   const sy = 0.5 + (this._shrines[i].y - camPos.y) / viewH;
   ```
4. Удали строку с `console.log('[fog:update] ...')` (строка 305), так как она вызывает спам в консоль каждый кадр и снижает производительность.
5. Удали неиспользуемую переменную `screenSize` и строки её получения (строки 274-276), т.к. `screenW`/`screenH` больше не используются.
6. Сохрани файл.

#### Шаг 2: Исправление разрешения рендеринга фильтра тумана (устранение "квадратов")
1. Открой файл `src/game/renderer/PixiJSRenderer.ts`.
2. Найди метод `createFullscreenQuad()`.
3. Измени присвоение ширины и высоты спрайта с логических размеров экрана на **физические** размеры canvas.
   **Было:**
   ```typescript
   sprite.width = this.app.screen.width;
   sprite.height = this.app.screen.height;
   ```
   **Стало:**
   ```typescript
   // Используем физические размеры canvas для предотвращения растяжения low-res текстуры фильтра
   sprite.width = this.app.canvas.width;
   sprite.height = this.app.canvas.height;
   ```
4. Сохрани файл.

#### Шаг 3: Финальная проверка типов и компиляции
1. Запусти команду сборки или проверки типов (например, `npm run build` или `npx tsc --noEmit`), чтобы убедиться, что изменения не нарушили типизацию TypeScript.
2. Убедись, что переменные `viewW` и `viewH` корректно передаются в метод `update` (они уже есть в сигнатуре метода, проверка нужна для уверенности).

### ✅ Критерии успеха

1. **Геометрическая точность:** При перемещении игрока по карте "дыра" (безопасная зона) в тумане остается строго центрированной на координатах святилища. Смещение вправо или вниз полностью отсутствует.
2. **Визуальное качество:** Туман отображается гладко, без видимых квадратных пикселей, блочности или артефактов растяжения низкого разрешения.
3. **Производительность:** В консоли браузера отсутствует покадровый спам логов `[fog:update]`.
4. **Геометрическая точность (дополнительно):** Дыра в тумане строго соответствует позиции святилища без смещения вправо/вниз.

### 🔧 Дополнительное исправление: смещение 0.5

**Дата исправления:** 2026-09-28
**Причина:** Формула `0.5 + (pos - cam) / viewW` предполагает, что `cam` — это центр камеры. Однако `cam` в игре — это **левый верхний угол** viewport (см. `CameraController.trackPlayer`: `cam.x = playerX - viewportW/2`).

При святилище в центре экрана: `sx = 0.5 + (viewW/2) / viewW = 0.75` — дыра смещается на 75% ширины экрана.

**Исправление:** Убрать `0.5 +`, использовать прямую нормализацию относительно левого верхнего угла viewport:
```typescript
// Было:
const uvX = 0.5 + (playerPos.x - camPos.x) / viewW;
const sx = 0.5 + (this._shrines[i].x - camPos.x) / viewW;

// Стало:
const uvX = (playerPos.x - camPos.x) / viewW;
const sx = (this._shrines[i].x - camPos.x) / viewW;
```
