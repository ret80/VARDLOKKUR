# Задача 22: Процедурная планировка Склепа (комнаты + коридоры + циклы)

## 1. Проблема

Первый данж (`genCrypt`, `id 0`, «Склеп Хранителя») был жёстко зашит:
сетка 6×4 из одинаковых прямоугольных комнат 9×8, соединённых коридорами
шириной 2–3, и захардкоженной ареной босса. Карта 60×45. Каждый забег
выглядел одинаково, комнаты не различались по форме/размеру, циклов
(петель) не было.

---

## 2. Решение — «cyclic room-and-corridor» (TinyKeep / Adonaac)

Классический современный подход, альтернатива BSP и клеточному автомату:
случайные комнаты разного размера → граф связей (MST) → дополнительные
рёбра-циклы → L-коридоры.

### 2.1. Чистая логика — `src/game/generators/dungeon-layout.ts` (новый)

Модуль не знает про ECS, рендер и даже про `Tl` — тайл пола передаётся
параметром. Экспортирует:

- `generateLayout(rng, W, H, opts)` → `DungeonLayout | null`.
- `carveLayout(tiles, W, H, layout, rng, floorTile, opts)` → `CarveResult`
  (`bossEntrance`, `bossOpenings`).
- `validateLayout(tiles, W, H, layout, floorTile, expectedOpenings?)` →
  `{ ok, unreachable, bossOpenings }` (flood-fill от входа).
- `findBossOpenings(tiles, W, H, bossRoom, floorTile)` — открытые тайлы в
  стене-периметре комнаты босса.
- `graphDistances(layout)` — расстояния в рёбрах от входа (BFS).

Конвейер генерации:

1. **Размещение комнат** (`placeRooms`): категории размеров (малая 6×5,
   средняя 9×7, большая 12×9, галереи 15×6 и 6×12) с весом; паддинг 2 и
   отступ 3 от краёв; отбраковка пересечений.
2. **Форма** (`pickShape`): `rect` / `L` / `cross` / `round` по весу, но
   сложные формы только для достаточно крупных комнат.
3. **Граф** (`buildGraph`): все пары → Kruskal-MST (гарантия связности) +
   дополнительные короткие рёбра (петли; `d ≤ 1.5·meanD`, шанс 18%).
4. **Вход** (`pickEntry`): комната, ближайшая к нижнему центру карты.
5. **Босс** (`pickBoss`): самый далёкий от входа **лист** MST (тупик).
6. **Ширина**: рёбра главного пути (вход→босс) — `mainWidth` (3), прочие —
   `corridorWidth` (2). Ребро босса принудительно = 2 (см. §2.3).
7. **Арена босса** (`expandRoom`): расширение до `bossMinW×bossMinH` по
   свободному месту, форма → `rect`.

### 2.2. Вырезание пола (`carveLayout`)

- Комнаты (кроме босса) и обычные коридоры вырезаются первыми.
- Прямоугольник босса защищается (`protect`), чтобы случайный коридор не
  пробил лишний проход в его стену.
- Затем вырезается комната босса и **ровно один** коридор к ней.
- `carveCorridor` — L-образный: ось выбирается по **неперекрывающейся**
  стороне комнат, полоса прижимается через `safeBandStart` так, чтобы не
  идти вдоль стен. Благодаря этому дальняя комната (в т.ч. босс) всегда
  получает ровно `width` непрерывных проходов.
- `carveH`/`carveV` трактуют координату как НАЧАЛО полосы (а не центр).

### 2.3. Герметичная дверь босса

Коллайдер двери — 18×16 px (`ecs-map-loader.ts`). Проход шириной 2 тайла
= 32 px; дверь по центру оставляет зазоры 7–8 px < диаметра игрока (10 px),
поэтому арена реально заперта. Проход ширины 3 (48 px) дверь бы не
закрыла — отсюда форсированный `bossEdge.width = corridorWidth`.

## 3. Интеграция — `src/game/generators/dungeons.ts`

- `CRYPT_W = 88`, `CRYPT_H = 60` (было 60×45).
- `CRYPT_LAYOUT` — опции: 14 комнат (мин. 8), арена босса 16×12.
- `genCrypt`:
  - до 20 попыток: `generateLayout` → `carveLayout` → `validateLayout`;
    первая валидная принимается (иначе — резервная карта);
  - вход: лестница + спавн в комнате входа;
  - босс: `bossRoom`/`bossSpot`/дверь из `carveLayout.bossEntrance`;
  - колонны (`Tl.COLUMN`) в больших залах — только на открытых площадках;
  - ключ — в самой далёкой от входа комнате (кроме босса);
  - враги — плотность растёт с размером комнаты и расстоянием от входа;
  - декор (`ambient`): осколки/кости.
- `fallbackCrypt` — резервная карта на случай, если все 20 попыток не
  прошли валидацию (широкий зал + арена босса + проход ширины 2).
- `finalizeDungeon`:
  - дверь босса теперь создаётся **только если `w.doors` пуст** (генератор
    уже задал корректную дверь); авто-подбор оставлен для прочих данжей;
  - лимит спавнов поднят 16 → 24 (карта крупнее).

Логирование генератора — через `logger.info` (не `debug`): `logger.debug`
шлёт лог через `sendLogToServer`, который обращается к `window` без guard и
падает под Node/vitest.

## 4. Тесты — `src/game/__tests__/dungeon-layout.test.ts` (новый)

7 тестов (vitest):

1. Детерминизм: одинаковый seed → одинаковая планировка.
2. Комнаты в границах карты (30 сидов) и не пересекаются.
3. Граф связен: все комнаты достижимы от входа (30 сидов).
4. Босс — тупик (ровно одно ребро) и далеко от входа (30 сидов).
5. `carveLayout`: пол связен, у босса ровно один проход ширины 2 (30 сидов).
6. `generateDungeon` детерминирован (одинаковые `tiles`).
7. Инварианты `generateDungeon` на 12 сидах: `W/H`, спавн/лестница на
   проходимом, `bossRoom` в границах, `bossSpot` на полу, ровно 1 дверь,
   ровно 2 тайла прохода в арену, ключ есть и достижим, босс достижим,
   спавны > 0.
