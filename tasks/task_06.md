### 🔴 Регрессия 2: Низкий FPS и высокая нагрузка на ЦПУ

Эта проблема является прямым следствием рефакторинга *"migrate ECS rendering to Graphics API"*. Нагрузка на ЦПУ взлетела по трем основным причинам:

1. **Отсутствие Viewport Culling для статических объектов:**  
   В методе `renderObjectsEcs` (для сундуков, пьедесталов, святилищ, дверей, барьеров, алтарей) **нет проверки** `r.isVisibleInViewport`. В отличие от врагов, эти объекты перерисовываются и обновляются каждый кадр, даже если они находятся далеко за пределами экрана.
   ```typescript
   // В renderObjectsEcs отсутствует эта проверка, которая есть для врагов:
   // if (!r.isVisibleInViewport({ x: px, y: py }, radius)) continue;
   ```

3. **Избыточные итерации по сущностям:**  
   В методе `render()` класса `RenderSystem` присутствуют три последовательных полных цикла по `query(world, [SpriteComp])` (для позиции, видимости и zIndex), плюс дополнительные итерации в `renderByRegistry` и `renderObjectsEcs`. При большом количестве сущностей это создает значительные накладные расходы на обход массивов.

**✅ Решения для оптимизации:**
1. **Добавить отсечение по виду (Viewport Culling)** в `renderObjectsEcs` перед вызовом `r.setGraphicsPosition` и `render`.
3. **Объединить циклы обновления.** Вместо трех отдельных циклов для позиции, видимости и zIndex, сделайте один проход по `query(world, [Position, SpriteComp])`, в котором обновляются все три свойства сразу. Это сократит время обхода сущностей в 3 раза.
