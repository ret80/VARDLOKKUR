# Задача 21: Мультитайловый тайлсет подземелий (DWALL 2.5D)

## 1. Проблема

Стены подземелий рисовались одним повторяющимся блоком `Tl.DWALL`
(`wall-geom.ts` → `case Tl.DWALL`: тёмная заливка + светлая полоса сверху).
Все стены выглядели одинаково, углы/Т-стыки/торцы/фасады не различались.

Эталон тайлсета и правила стыковки: `SVG/tile_set_d01.svg`
(19 уникальных тайлов `t00`–`t18` + пример сборки сетки 7×11).

---

## 2. Правило тайлсета (из SVG)

Тайл стены = **slab-основа** + канты по N/E/W + фасад-кирпич на юге:

| Сосед стороны | Что рисуется |
|---------------|--------------|
| стена         | нейтрально (ничего) |
| пол           | светлый кант `#4a5563` + `#2b333d` |
| пустота (за границей) | тёмный контур `#1a222c` + `#2b333d` |

Юг **открыт** (пол ИЛИ пустота) → фасад-кирпич `bF` (линия `#202832` + паттерн `brk`).
Пол (`t00`) = заливка `#141a22` + линии сетки `#0a0e14` сверху/слева.

Полное пространство тайлов: N/E/W ∈ {стена, пол, пустота} (3³) × юг
{закрыт, открыт} (2) = **54 тайла стены** + 1 тайл пола.

## 3. Решение

### 3.1. Чистая логика автотайлинга — `src/game/dungeon-tiles.ts`

- `DSide` — класс соседа (`Wall`/`Floor`/`Void`).
- `wallTileCode(n, e, s, w)` — код тайла 0..53:
  N/E/W в базе 3 + младший бит «юг открыт».
- `decodeWallCode(code)` — разбор кода.
- `dungeonWallCodeAt(map, x, y)` — код по окружению.
- `resolveDungeonTiles(w)` — заполняет `WorldData.dungeonWall`
  (`DUNGEON_FLOOR` для пола, 0..53 для стен).
- `DUNGEON_FLOOR = 255`.

### 3.2. Отрисовка — `src/game/geometry/dungeon-tile-geom.ts`

- `DungeonPalette` + `dungeonPalette(dungeonId)`:
  id 0 — базовая синеватая (1-в-1 цвета SVG);
  id 1 — зелёная, id 2 — бурая (детерминированный тинт базовой).
- `drawDungeonFloor(...)` — тайл `t00`.
- `drawDungeonWall(renderer, g, code, ox, oy, pal)` — тайл стены по коду.
- `drawDungeonFloorBatch(...)` / `drawDungeonWallBatch(...)` — единые
  батч-Graphics на всю карту.

### 3.3. Генерация — `src/game/generators/dungeons.ts`

- `baseDungeon` создаёт `dungeonWall: new Uint8Array(W * H)`.
- `finalizeDungeon` вызывает `resolveDungeonTiles(w)` после всех правок
  `tiles` и до построения навигации.

### 3.4. Тип — `src/game/generators/types.ts`

- `WorldData.dungeonWall?: Uint8Array` (опционально, чтобы не ломать
  `createTestMap` и overworld).

### 3.5. Рендер — `src/game/render/map-render-system.ts`

- Для `isDungeon`:
  - ground = `drawDungeonFloorBatch` (пол `t00`, прочие тайлы — как раньше);
  - стены `DWALL` = ОДИН батч `_dungeonWallGraphics` (широкий bbox,
    слой `DYNAMIC`), per-tile цикл пропускает `DWALL`;
  - `COLUMN` и прочие стены — по-прежнему per-tile (Y-sort).
- Устранён двойной проход `DWALL` (раньше: ground-батч + wall-слой).
- `_dungeonWallGraphics` сбрасывается в `createMapTileGraphics` и
  уничтожается в `destroyAllMapTileGraphics`.

### 3.6. Fallback цвета — `src/game/geometry/tile-geom.ts`

- `case Tl.DFLOOR` → тёмный пол `t00` (`#141a22` + линии сетки).
- `case Tl.DWALL` → нейтральная тёмная подложка (основной путь — батч стен).

## 4. Тесты — `src/game/__tests__/dungeon-tiles.test.ts`

6 тестов (vitest):

1. Все 77 тайлов примера 7×11 решаются ровно как в SVG.
2. Пол → `DUNGEON_FLOOR`, стена → 0..53.
3. Код стены покрывает все 54 комбинации N/E/W/юг.
4. `decodeWallCode` обратим.
5. `t06 == t11` (юг: пол/пустота неразличимы — задокументированный дубль).
6. `dungeonWallCodeAt` совпадает с `resolveDungeonTiles` для стен.

Дополнительно (вне репозитория, разово) выполнена **попиксельная сверка**:
для каждого из 19 тайлов состав из SVG (`<use>` + паттерны `slab`/`brk`)
сравнен с выводом `drawDungeonWall`/`drawDungeonFloor` — совпадение 1-в-1.
